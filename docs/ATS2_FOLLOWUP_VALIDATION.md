# Инвентарь, замена батарей и свободные дроны

2026-10-16. Исправления ATS 2.0; вода и водная эрозия не добавлены.

Окно склада и основная телеметрия больше не сериализуют всю историю заданий.
Таблицы обновляются только на открытой вкладке, существующие ячейки используются
повторно, автоматический пересчёт ширины всех столбцов отключён. Окно переиспользуется,
таймер останавливается при закрытии. Диспетчер показывает последние 200 заданий;
полный JSON-отчёт по-прежнему содержит весь архив и инвентарь.

Механическая замена батарей имела рабочий физический цикл, но её состояние
перезаписывалось диспетчером как `CHARGING`. Теперь видны `SWAPPING_BATTERIES`,
ID снятых/устанавливаемых модулей, оставшееся время и число замен каждого дрона.
Проверены резервирование полного совместимого комплекта, 60 секунд механики,
атомарная смена ID и последующая зарядка снятых модулей по одному на порт.
Во время механической замены контактная зарядка и назначение рейса исключены.
Если полный совместимый комплект отсутствует, остаётся контактная зарядка до 100%.
Короткая миссия может закончиться до достижения нижнего порога SOC.

Свободные перевозчики после 30 секунд ожидания получают задания на копание.
Для этого дрон действительно летит к свободному посадочному доку, резервирует
два инструмента и за 45 секунд при 100 Вт меняет подвес на складской грейфер.
Масса и мощность полёта меняются вместе с установленным инструментом. Один
контейнерный аппарат остаётся в транспортном резерве. При отсутствии подвеса
появление грузового задания отзывает одного копателя после выгрузки его текущего
грунта; выполняются обратный перелёт и обратная смена инструмента. Перед переносом
Крота прямые рейсы тоже заканчиваются. Зарядка имеет приоритет над сменой инструмента.
Занятый свободным аппаратом сервисный док освобождается реальным перелётом на
площадку ожидания. Один дрон не может одновременно владеть прямым и транспортным
заданием. Эта логика включена в ATS 2.0 по умолчанию; `--no-idle-digging` сохраняет
строгий режим перевозчиков. Переключатель также есть в настройках эксперимента.

## Время интерфейса

Linux, Python 3.12.14, numpy 2.5.4, PySide6-Essentials 6.12.0, Qt offscreen.
При 100 000 архивных заданий полный отчёт занимает 583 мс, показ вкладки инвентаря
около 17 мс, повторное обновление инвентаря 5,27 мс, диспетчера 5,59 мс.
Это локальные замеры, зависящие от машины. Регрессионный GUI-тест запрещает
обход архива целиком при обновлении основного окна и всех вкладок склада,
проверяет повторное открытие и сохранение существующих ячеек.
[Исходные замеры](ats2/inventory-timings.json).

## Сквозные прогоны

Одинаковые seed 42, рельеф, четыре дрона, восемь контейнеров, четыре модуля Крота,
одинаковый конечный запас батарей, 20 м² панелей и отключённый лазер. Меняются
только совместное копание и число посадочных слотов. Зарядных портов снятых
модулей везде четыре. Максимум четыре дня симуляции; все шесть прогонов завершены,
весь грунт выгружен, все аппараты приземлились. Допуск завершения 0,05 м³ одинаков;
фактические остатки приведены в JSON. Время ниже — симуляционное.

## Воспроизведение

```bash
python -m pip install -e ".[test]"
python -m pytest -q
python -m ats --mode logistics
python -m ats --headless --mode logistics --preset medium --steps 345600 --json auto.json
python -m ats --headless --mode logistics --preset medium --no-idle-digging --steps 345600 --json strict.json
python -m ats --headless --mode logistics --preset medium --charge-slots 1 --steps 345600 --json one-pad.json
```

Жадное планирование и модель воздушного переноса сохраняют прежние ограничения.
Прямое копание допускается только при наличии независимого доступного участка и
энергии на рейс с резервом. Батареи и оборудование берутся из конечного инвентаря.
