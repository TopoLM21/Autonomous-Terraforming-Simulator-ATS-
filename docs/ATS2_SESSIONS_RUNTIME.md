# Сохранение симуляции, оборудование и скорость расчёта

## Сохранить и продолжить

**Файл → Сохранить симуляцию…** (`Ctrl+S`) создаёт `.atsstate`.
**Файл → Загрузить симуляцию…** (`Ctrl+O`) восстанавливает эксперимент на паузе;
нажмите Start для продолжения. «Сохранить как…» — `Ctrl+Shift+S`.
При сохранении работа продолжится после записи файла. Время файлового диалога
не добавляется к модельному времени.

Сохраняются время, текущий рельеф и MSL-привязка, региональный DEM и изменённые
блоки, грунт в ковше и контейнерах, позиции и состояния дронов и Крота,
индивидуальные заряды батарей, смена оборудования, зарядные слоты, задания,
резервы, коллективные переносы, переезд базы, развёртывание панелей, пыль,
лазерные состояния, энергетические балансы, журнал событий и статистика.
Сохраняются также масштаб, ускорение, режим отображения, выбранный профиль
и ещё не применённый рисунок кисти.

Сохранение разрешено в полёте и в середине операций: командовать посадку не
требуется. Файл записывается через временный файл и атомарную замену; ошибка
записи сохраняет прежнее сохранение. Ошибка чтения не заменяет текущий мир.
Архив содержит JSON со ссылками на физические экземпляры и массивы NumPy,
загружаемые без pickle. DEM включён в файл; исходный файл и интернет для
возобновления не нужны. Формат имеет собственную версию.
В файл записываются версии Python и NumPy. Побитовое продолжение проверено
в одной программной среде; при смене версий численных библиотек возможны
различия в последних разрядах вычислений.

Для контрольного участка 1024² с включённым региональным DEM файл составил
74,1 МБ: запись 2,30 с, чтение с проверкой 0,67 с на тестовой машине.
На время файловой операции интерфейс ждёт её окончания.

Старые «Сохранить конфигурацию» и `.atsregion` остаются доступны: конфигурация
создаёт новый эксперимент, регион хранит рельеф. Для продолжения текущей работы
со всеми зарядами и заданиями используйте `.atsstate`.

```bash
python -m ats --headless --preset medium --steps 1000 --save-state work.atsstate
python -m ats --load-state work.atsstate
python -m ats --headless --load-state work.atsstate --steps 1000 --save-state continued.atsstate --json report.json
```

При загрузке параметры нового сценария (`--seed`, `--preset`, `--configuration`
и прочие) не применяются: сценарий уже находится в сохранении. Можно явно
изменить панели и батареи базы через `--panel-area` и `--base-batteries`.

## Оборудование без перезапуска

В блоке **База и солнце** задайте площадь панелей или количество аккумуляторов
и нажмите соответствующую кнопку **Применить … сейчас**. Дроны могут продолжать
рейсы; база должна стоять. Грунт, время, задания, статистика и заряды остаются.
Доступно до 1000 установленных батарей базы.

Новые батареи поступают пустыми: количество увеличивает ёмкость и массу,
а энергия не создаётся. Быстрый счётчик добавляет первый указанный тип;
его ёмкость и масса показаны рядом. При уменьшении сначала снимаются последние
типы. Для выбора отдельных типов откройте **Оборудование → База**.
Масса и энергия вывезенных батарей учитываются в балансе.

Уже развёрнутая часть панелей продолжает вырабатывать при добавлении новых.
Новые панели требуют места и времени развёртывания. Состав оборудования и
незавершённые операции сохраняются вместе с симуляцией.

## На что тратится время

Физический шаг всегда **1 с**. Ускорение 2000× означает цель выполнить 2000
последовательных шагов за реальную секунду. Шаг не укрупняется и операции не
пропускаются. Ограничения «не выше 15×» и требования 60 кадров/с в движке нет.

Профиль исходной версии на контрольном канале Каттары (512 м, сетка 1024²,
четыре дрона, 1200 шагов, Python 3.12):

| Участок расчёта | Время профилированного прогона | Доля от 9,11 с |
| --- | ---: | ---: |
| Поиск точки выгрузки | 2,31 с | 25% |
| Перенос/диффузия пыли | 1,70 с | 19% |
| Осыпание, включая выбор локальных пар | 0,76 с | 8% |
| Обновление фронта работ | 0,65 с | 7% |
| Распределение выгружаемого грунта | 0,51 с | 6% |
| Остаток выемки и засыпки | 0,42 с | 5% |

В отдельном профиле GUI около 61% времени занимали физические шаги,
23% — подготовка карты и телеметрии, ещё около 8% — рисование Qt.
В подготовку входит раскраска всей миллионной сетки даже при общем масштабе.
Профилирование само замедляет выполнение; скоростные замеры выполняются
отдельно, без профилировщика.

Внесённые изменения:

* Сводные данные отвала пересчитываются после изменения самого отвала.
  Выемка на другом участке больше не запускает этот пересчёт.
* При равномерном ветре пыль переносится срезами массивов вместо четырёх
  полных операций с индексами. Сохранены исходные веса и порядок сложения;
  для особых округлений действует прежний алгоритм. Проверено побитовое
  совпадение с исходной формулой, включая дробный ветер и изменение шага пыли.
* **Карта: авто** отображает большой участок усреднёнными пикселями и
  ограничивает долю времени на перерисовку. При приближении возвращаются
  отдельные ячейки. Физическая сетка, масса и высоты не усредняются.
* **Карта: подробно** сохраняет полное отображение. **Без карты** отключает
  карту и профиль, оставляя расчёт и телеметрию; выбор доступен в строке состояния.
* Между обработкой интерфейса допускается до 50 мс расчёта на высоких скоростях.
  Индикатор фактического ускорения учитывает время перерисовки и сглаживает
  колебания. Сама скорость выполнения шагов не подменяется показателем.

Вычисление идёт в одном потоке Python с операциями NumPy. Полностью занятое
одно ядро на восьмиядерном компьютере выглядит как примерно 12,5% общей
загрузки. Низкая суммарная загрузка не означает, что текущий расчёт способен
занять остальные ядра. Другая карта, большой инвентарь, активное окно склада,
лазеры, планирование рейсов и осыпания меняют стоимость одного шага.

## Контрольный замер до и после

Одна машина Linux, Python 3.12.14, Qt offscreen; канал Каттары 512×512 м,
1024×1024 ячейки по 0,5 м, четыре дрона, 93 предмета инвентаря.
По три последовательных прогона каждого варианта, ровно 1200 физических шагов.
В таблице медианы, без загрузки и создания мира, без профилировщика.
Исходная версия — `97284aa`.

| Режим | До: время / ускорение | После: время / ускорение | Прирост скорости |
| --- | ---: | ---: | ---: |
| Без интерфейса | 8,23 с / 146× | 6,67 с / 180× | +23% |
| Интерфейс с картой | 11,85 с / 101× | 8,98 с / 134×, авто | +32% |
| Интерфейс без карты | — | 7,08 с / 170× | +68% к исходному GUI |

Во всех 15 прогонах совпал SHA-256 **полного физического отчёта**:
`07ce0111ef315b4de14a716208593bb5c13da706692bd3e0e941c6054644540c`.
В каждом выполнено 85 рейсов. Ошибка массы — менее `6×10⁻¹³` кг,
энергии — менее `6×10⁻⁷` Дж. Настройки физики и шаг сохранены.
[Исходные замеры и профили функций](ats2/sessions-runtime-performance.json).

Это замер контрольного сценария на сервере. Наблюдаемые у пользователя 15×
без его сохранения и характеристик машины пока не воспроизведены.
В данной версии остаются затратными поиск точки выгрузки, осыпания и фронт
работ. Их можно ускорять дальше; распараллеливание отдельных дронов требует
согласования общего рельефа, инвентаря и резервов, поэтому простое добавление
потоков Python не даёт гарантированного ускорения.

## Измерить свою симуляцию

Сохраните проблемный момент через Ctrl+S, затем выполните:

```bash
python scripts/benchmark_runtime.py --state work.atsstate --steps 1200 --trials 3 --mode both --output speed.json
python scripts/benchmark_runtime.py --state work.atsstate --steps 1200 --trials 3 --mode gui --render off --output without-map.json
python scripts/benchmark_runtime.py --state work.atsstate --steps 1200 --trials 1 --mode both --profile profile --output profile.json
```

Без `--state` используется встроенный офлайн-сценарий Каттары. Для сервера без
экрана добавьте `--offscreen`. Скрипт печатает реальное ускорение, время расчёта
и загрузки, ошибки балансов и SHA-256 полного физического отчёта. Профиль
сохраняется в JSON и `.prof`, который можно открыть через `python -m pstats`.
Профилированные прогоны не смешиваются с обычными в медиане.

Если тормозит и headless, ограничение находится в расчёте. Если заметно
тормозит только GUI, сравните «Авто» и «Без карты», закройте подробную таблицу
зарядных слотов и повторите замер. Значения 1000×/2000× остаются целями,
а не гарантией для любого оборудования и состояния эксперимента.

## Проверки

Полный локальный набор: **326 passed, 225,21 с**. Отдельно проверены
перелёт с грунтом, физическая смена батарей и инструмента, груз в контейнере,
коллективный подъём Крота, пыль с активным кэшем переноса, региональный DEM,
незавершённое развёртывание панелей и горячее добавление 100 батарей.
Восстановление ссылок на те же физические экземпляры и точное продолжение
сравниваются с непрерывным прогоном; испорченный файл не заменяет текущий мир.
В CI добавлено сравнение двух CLI-запусков «75 шагов → сохранить → 125 шагов»
с непрерывными 200 шагами на Ubuntu/Windows и Python 3.11/3.12.

После финальных изменений интерфейса и исправления `--help` отдельный набор
CLI/GUI прошёл **23 теста за 9,79 с**. Итоговый полный набор в CI:
