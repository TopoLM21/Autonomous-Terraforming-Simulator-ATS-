# Фронт канала, боковые отвалы и переезды базы

Подготовленные проекты канала теперь работают последовательно от начала
маршрута. Одновременно вырабатывается полоса до 32 м вдоль трассы (на картах
меньше 96 м полоса уменьшается). «Крот» и дроны выбирают работу в этой области.
Зелёная пунктирная рамка показывает её на локальной карте; положение фронта и
состояние переезда указаны над прогрессом.

Отвалы идут по обеим сторонам канала. При их построении учитывается вся
проектная выемка с окончательными откосами, включая уже выкопанные ячейки.
Свободный промежуток между откосом и отвалом составляет 6–24 м и учитывает
площадки флота и размер карты. Это одновременно служебная полоса для базы.
Предел высоты каждого отвала плавно уменьшается до нуля у его границы.

Дроны выбирают ближайшие пригодные точки в рабочей области и ближайшие
свободные площадки выгрузки рядом с местом выемки. При почти одинаковой длине
пути предпочтение получает менее заполненный берег. Прямые перелёты сохраняют
проверку разделения дронов и локальные обходы встречного движения. Это
эвристика коротких безопасных рейсов, без глобального оптимизатора воздушного
движения.

Груз выгружается только возле выбранной точки: распространение ограничено
радиусом 2 м либо большим физическим радиусом грейфера. Если площадка занята
или заполнена, аппарат сохраняет груз и летит к следующей. Контейнерные
задания и прямые копатели учитывают зарезервированные места выгрузки.

База размещается возле начала оставшейся выемки. После продвижения примерно
на половину рабочей полосы новые вылеты приостанавливаются; флот завершает
рейсы и садится. Для переезда достаточно посадки на землю: четыре дрона с
одним зарядным слотом не ждут невозможной одновременной стыковки. Пристыкованные
аппараты и оборудование базы переезжают вместе с ней; ожидающие на грунте
аппараты остаются на своих площадках и затем выполняют обычные перелёты.

Переезд имеет конечную скорость и расход энергии, зависящий от физической
массы. Подъём по рельефу дополнительно расходует `m·g·Δh / 0,8`; рекуперация
спуска не предполагается. Высота базы следует текущему грунту. Большое поле
панелей сначала сворачивается и затем разворачивается: каждый этап занимает
заданное в конфигурации время и потребляет 200 Вт автоматики. Во время
сворачивания, движения и развёртывания генерация отключена. Заряды батарей,
массы инвентаря и накопленная статистика сохраняются.

«Крот», которому нечего достать из устойчивой позиции, освобождает остаток
для дронов. При необходимости применяется существующая процедура группового
переноса с физическим снятием батарей и такелажем. Небольшой суммарный остаток
до 10% общего допуска завершения не удерживает фронт на одном месте: грунт
сохраняется в плане и балансе, остаётся доступным для копания и входит в
общий остаток. Допуск завершения миссии не увеличивается.

## Запуск

```bash
git pull
python -m ats --qattara --channel-route docs/ats2/qattara-channel.json
python -m pytest -q
```

Для сохранённого `.atsregion` откройте проект через окно ландшафта и снова
запустите выбранный рабочий участок: новая организация применяется при
подготовке участка. Рельеф сохраняется; уже работающий процесс Python не
подменяет диспетчер посреди рейса. Старые конфигурации с вручную заданным
единственным отвалом остаются совместимыми.

## Производительность

В CI прошли **273 теста на каждой из четырёх конфигураций** Ubuntu/Windows,
Python 3.11/3.12. Проверены переезды с одним посадочным слотом на четыре
дрона, сворачивание панелей, сохранение груза, ручная посадка и освобождение
заданий, численная эквивалентность локального осыпания и балансы массы/энергии.
Также прошли CLI-прогоны прежнего движка, ATS 2.0, строгой логистики, DEM
и подготовленного канала. [Запуск CI](https://github.com/TopoLM21/Autonomous-Terraforming-Simulator-ATS-/actions/runs/39426033674),
[машинные результаты](ats2/workfront-ci-results.json). Локальные проверки
и их длительность записаны в `ats2/workfront-validation.json`.

Три последовательных прогона до и после изменения на одной машине,
Python 3.12 / NumPy 2.5.4. Реальный ETOPO1 Каттары, карта 512 м,
сетка 1024² с шагом 0,5 м, четыре стандартных дрона и стандартная энергетика.
Каждый прогон — 180 модельных секунд. В таблице медианы; это измерение
вычислительного движка без перерисовки Qt.

Убраны повторные обходы всего отвала для каждого кандидата рейса, полная
сетка досягаемости «Крота» каждую секунду и копирование миллионных списков
при проверке параметров. Осыпание использует те же консервативные парные
переносы в области изменений. Численный тест сравнивает его с полными
проходами; баланс массы сохраняется. Записи измерений:
[`ats2/workfront-validation.json`](ats2/workfront-validation.json).

Повторить замер: `python scripts/benchmark_canal.py --output benchmark.json`.

Дополнительно выполнен час модельной работы этой же конфигурации с обычными
18 кВт мощности зависания: 85 выгрузок, 3,4634 м³ выемки, 40 циклов «Крота».
Ошибка баланса массы составила 5,68·10⁻¹³ кг, энергии — 4,99·10⁻⁷ Дж.
На конец часа флот заряжается, «Крот» ожидает возврата тары; аварийной
блокировки и активных незавершённых грузовых назначений нет.

Целевые 1000×/2000× остаются целями ускорения, фактическая скорость зависит от
оборудования, карты, количества машин и осыпания. Ограничения грубого DEM и
перехода **между** локальными окнами сохраняются: физические переезды этой
версии относятся к одному рабочему окну. При непроходимом склоне база
остаётся на безопасной позиции с причиной в отчёте; универсального поиска
наземного маршрута вокруг произвольных препятствий пока нет.

Вода и эрозия не добавлены.
