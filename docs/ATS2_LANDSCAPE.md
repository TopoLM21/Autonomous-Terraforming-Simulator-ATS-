# Офлайн-ландшафт, MSL и конечная скорость копания

Открыть карту сразу:

```bash
git pull
python -m pip install -e ".[test]"
python -m ats --qattara
```

Для обычного запуска `python -m ats` есть кнопка **Ландшафт / импорт DEM…** рядом
с инструментами масштаба. Исходная карта Каттары включена в пакет; приложение
не скачивает файлы и не обращается к интернету. PySide6 Addons не нужны.

## Скорость копания

Раньше стандартный грейфер уже ждал 10 с, но снимал весь грунт в последний тик.
Теперь груз прибавляется каждый физический шаг, одновременно убывая из рельефа.
Для стандартного дрона: максимум **6 кг/с**, до **60 кг за 10 с**, плюс **5 с на
опускание** и **5 с на подъём**. Перелёт, выгрузка, зарядка и смена инструмента
учитываются отдельно. При плотности 1600 кг/м³ скорость самого набора составляет
0,00375 м³/с, или 13,5 м³/ч; фактическая суточная выработка существенно ниже.

Продолжительность набора = `max(scoop_seconds, масса / dig_rate_kg_s)`.
Ковш 120 кг при том же приводе требует минимум 20 с. Если груз меньше полного,
минимальная длительность закрытия грейфера сохраняется. Дробные длительности
интегрируются шагами 1 с с ограниченным последним приращением.

В **Оборудование → Дроны → настройки выбранного → Подробные параметры** есть
предел кг/с, минимальное время захвата и удельная работа копания. По умолчанию
удельная работа — 100 кДж/м³ для рыхлого песка: это настраиваемое инженерное
допущение, не калибровка под скалу. Расход на копание прибавляется к мощности
висения; растущий груз увеличивает потребление. Планировщик учитывает эти затраты
и резерв до назначения рейса. CLI: `--dig-rate 3`.

Крот сохраняет отдельный цикл: ковш 15 л × 0,75 заполнения = 18 кг песка,
35 с на цикл, 2,5 кВт в работе. В середине цикла грунт переходит в ковш,
в конце — в контейнер; грунт во всех состояниях включён в общий баланс.

## Работа с регионом

1. Откройте **Ландшафт / импорт DEM…**. Карта показывает весь исходный DEM.
   Для готового проекта канала используйте [новый маршрутный процесс](ATS2_CHANNEL_PROJECT.md):
   «Разметить канал → Начать копание выбранного участка». Ниже описан ручной выбор окна.
2. **Пример: море → Каттара** строит иллюстративную прямую и продольный профиль.
   Или включите **Рисовать коридор** и добавляйте вершины ЛКМ. Дно задаётся как
   абсолютная отметка MSL, ширина — в метрах. Профиль и оценка выемки не меняют
   грунт. Линия сохраняется вместе с ландшафтом.
3. Выключите рисование коридора и выберите ЛКМ рабочую площадку. Колесо
   приближает карту; начало X/Y можно задать точно. Выберите сторону 32–1024 м; для 512/1024 м применяется ячейка 0,5/1 м.
4. **Открыть участок · новый локальный запуск** создаёт обычную симуляцию ATS 2.0
   на выбранном реальном рельефе. Сам импорт не назначает выемку. Кистью задайте
   локальную линию, ширину и отметку дна, затем примените план и запустите флот.
   −5 м MSL означает 5 м ниже моря; при поверхности +20 м это 25 м выемки.
   Там, где поверхность уже ниже −5 м, режим выемки ничего не добавляет.
5. Для сохранения или смены участка нажмите **Посадить флот** в инструментах
   кисти: машины должны завершить переносы и выгрузить контейнеры. Затем
   **Сохранить ландшафт…** создаёт `.atsregion` с исходным DEM, линией и изменениями.
   Возвращение к обработанному участку восстанавливает его грунт и отвалы.

Смена участка начинает новый локальный запуск оборудования и статистики.
`.atsregion` хранит рельеф и коридор, не состояние летящих машин или аккумуляторов.
Обычные сохранения конфигурации/плана сохраняют исходные абсолютные высоты и MSL.
При переходе к другому региону сначала сохраните предыдущий файл.

## Форматы импорта

- **NPZ:** массив `height` (float, строки с юга на север), строка JSON `metadata`.
  Обязательные поля: `crs`, `units`, `vertical_datum: "MSL"`, `x0`, `y0`, `dx`, `dy`.
  `x0,y0` — координаты первого отсчёта, шаги положительны. Поддерживаются WGS84
  `EPSG:4326` в градусах и спроецированные/локальные координаты с `units: "metres"`.
- **ESRI ASCII `.asc`:** стандартный заголовок из 6 строк, `xllcorner/yllcorner`
  либо `xllcenter/yllcenter`, `cellsize`, `NODATA_value`, строки с севера на юг.
  CRS и подтверждение MSL задаются в окне импорта, CLI или соседнем `.json`.
- **GeoTIFF:** дополнительная установка `python -m pip install -e ".[dem]"`.
  Поддерживаются north-up сетки WGS84 или проекции в метрах; учитываются
  NoData, scale/offset и положение центров пикселей. CRS читается из файла;
  подтвердите вертикальные метры MSL. Поворот, футы и неизвестные CRS требуют
  предварительного преобразования в GIS. Эллипсоидальную высоту нужно сначала
  привести к выбранной системе высот относительно моря, например через геоид.

Пропуски NoData в рабочем окне отклоняются; они не превращаются в нулевую высоту.
Данные других вертикальных датумов не преобразуются молча. Верхний предел
исходного DEM — 16 млн отсчётов: большой файл предварительно обрежьте в GIS.

CLI-примеры:

```bash
python -m ats --dem egypt.asc --dem-crs EPSG:4326 --dem-datum MSL \
  --work-lon-lat 28.3 31.0 --map-size 128
python -m ats --dem terrain.tif --dem-datum MSL --work-origin 1000 2000
python -m ats --headless --qattara --steps 0 --json qattara-info.json
python -m ats --landscape saved.atsregion --work-origin 1000 2000
```

`--goal-msl` назначает локальную канаву с абсолютным дном; без него импорт
создаёт пустой план. CLI сохраняет `.atsregion` через `--save-landscape` только
после посадки и выгрузки; незавершённый перенос отклоняется, не теряя груз молча.

## Память и физика

Регион не имеет сплошной мелкой сетки. Он хранит неизменяемый исходный DEM и
словарь изменённых блоков 64×64 fine-ячеек. При шаге 0,25 м блок охватывает
16×16 м и занимает 32 КиБ float64. Чтение или просмотр участка не создаёт
сохранённых блоков. Возврат исходной поверхности удаляет ненужный блок.
Один локальный движок использует плотные рабочие массивы ограниченного размера;
вне него подробные данные хранятся только для реально изменённых мест.

Офлайн-DEM Каттары занимает 580 328 байт в памяти, около 104 КБ на диске.
Сплошная сетка 0,25 м для всего этого региона потребовала бы **около 27 ТБ
только для одного массива высот**. Два изменённых блока требуют 64 КиБ.
Рабочие окна 512/1024 м используют более крупные средние ячейки, сохраняя объём
и уже существовавшие мелкие изменения в разреженном хранилище.
В отчёте есть `modified_tiles`, `fine_storage_bytes`, `soil_delta_m3`.

Положительные и отрицательные изменения одного инвентаря рельефа складываются
в один баланс объёма. Грунт в грейферах, ковше и контейнерах учитывается отдельно
движком. Ошибка массы вычисляется по разности высот, чтобы не вычитать большие
почти равные массы подстилающего слоя. Полёт и работа лебёдки используют
абсолютную Z и фактическую разность высот, а не высоту над морем как длину подъёма.
Естественные необработанные склоны DEM не осыпаются сами по себе.

## Ограничения

- Встроенный ETOPO1 имеет шаг **1 угловая минута**: около **1,6×1,85 км**.
  Интерполяция до 0,25 м не добавляет реальных подробностей. Для подробного канала
  загрузите более точную съёмку. [Источник и лицензия](../ats/data/README.md).
- Для WGS84 применяется локальная цилиндрическая проекция с масштабом
  по средней широте DEM. В пределах этого региона масштаб меняется примерно
  на 2%; для точных измерений используйте метрическую проекцию GeoTIFF.
- Маршрут канала теперь размечается целиком и открывает готовые планы по
  участкам. Одновременно моделируется **один локальный участок**. Нет сквозной автономной
  миссии на 200 км, межучастковых рейсов, автоматического передвижения базы по
  всему региону или обмена осыпанием через края локальных окон.
- Профиль коридора оценивает площадь `ширина × глубина + глубина² / tan(35°)`
  и интегрирует её вдоль линии; поперечный рельеф приближён постоянным.
  Это обзорная стоимость для будущего поиска маршрута, не инженерный подсчёт.
  Оптимизатор минимальной выемки/кратчайшего пути пока не реализован.
- DEM содержит геометрию, не геологию. Пока весь извлекаемый материал имеет
  заданные свойства песка. Нижняя расчётная граница импортированной площадки —
  −1000 м MSL либо на 100 м ниже самых низких данных, если они ещё ниже.
- Вода, затопление и водная эрозия не добавлены. Отрицательная высота сама по
  себе не отличает сухую впадину от дна моря.

Проверки и измерения этого изменения записаны в `docs/ats2/landscape-validation.json`.

## Испытания

Локально: **246 тестов, 0 ошибок, 0 пропусков**, 199,34 с; Python 3.12,
Qt offscreen, установлен дополнительный GeoTIFF-импорт. При установке только
`.[test]` проверка GeoTIFF пропускается, остальные работают без rasterio.
Сборка wheel проверена: исходный DEM входит в устанавливаемый пакет.

CI: **246 тестов прошли в каждой из четырёх конфигураций** Ubuntu/Windows,
Python 3.11/3.12. Также прошли legacy, обычная и строгая логистика,
офлайн-запуск Каттары. [Результат GitHub Actions](https://github.com/TopoLM21/Autonomous-Terraforming-Simulator-ATS-/actions/runs/39392149632),
машинный отчёт — `docs/ats2/landscape-ci-results.json`.

Одинаковая локальная канава на плоскостях +120 и −120 м MSL:

| Состав | Время миссии, с | Перемещено из выемки, м³ | Расход, кВт·ч |
| --- | ---: | ---: | ---: |
| Один грейфер, legacy | 4762 | 0,9804 | 7,7610 |
| Крот + четыре дрона, ATS 2.0 | 1572 | 0,9832 | 15,3858 |

Для каждого состава время и энергия совпали при обоих сдвигах высоты.
Разница итогового объёма между составами связана с допуском завершения.
Максимальная ошибка баланса массы в этих четырёх запусках — 1,33×10⁻¹⁰ кг,
энергии — 2,28×10⁻⁷ Дж. После сохранения участков остаток объёма всех блоков
по модулю меньше 10⁻¹³ м³.

Дополнительно завершена локальная выемка на **реальном ETOPO1** около
28,3° E / 31,0° N: абсолютное дно +58,715 м MSL, фактически извлечено
0,9903 м³; ошибка массы 1,85×10⁻¹¹ кг. Это проверка работы с исходными данными,
не расчёт полного канала через регион.
