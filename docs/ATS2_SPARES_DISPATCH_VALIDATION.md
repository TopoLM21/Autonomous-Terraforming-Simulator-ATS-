# Запасные батареи и простой DOCKED

2026-10-16. Расширение существующей ATS 2.0; вода и эрозия не добавлены.

## Воспроизведение ошибки и исправление

На прежнем коде `72d4512` сценарий medium, seed42, четыре дрона имел ложный простой
**7786–16417 с**: два, затем три копателя стояли `DOCKED` с полными батареями и
доступными рейсами. В очереди ждали контейнеры и батареи, единственный дрон с
подвесом заряжался либо последовательно обслуживал очередь. Коллективного переноса
в этот период не было. Любая задача `QUEUED` глобально запрещала копание, а
заряжающийся перевозчик ошибочно считался доступным для перевозок.

Теперь диспетчер подбирает готовых исполнителей для ожидающих грузов. При
необходимости готовый копатель физически меняет инструмент; остальные копают
независимо от очереди. Готовность учитывает зарядный запрос, занятость и смену
инструмента. Назначение не меняет чужое резервирование. Прямой рейс начинается
только после успешного резервирования своего грейфера.

Второй дефект: наземный копатель с SOC чуть выше 30%, но недостаточной энергией
на минимальный безопасный рейс, мог ждать без запроса зарядки. Теперь доступность
рейса с полной батареей вызывает запрос полной зарядки. Проверка работает также
до установки более тяжёлого грейфера. Перед совместным переносом заряд запрашивается
только у недостаточно готовых участников; существующий запрос обязательно
выполняется до 100%. Причины ожидания показаны на карте и в подсказке состояния.

Совместному переносу по-прежнему нужна готовая команда. Ожидание её участника,
зарядного дока, питания или доступного участка остаётся физическим ограничением.
Исправление не обещает непрерывный полёт каждого аппарата. На прежнем коде перенос
мог прервать запрос полной зарядки при достижении лишь достаточного запаса; теперь
это исключено. Поэтому общее время миссии не обязано уменьшаться при прежнем запасе.

## Настройка склада

В окне **ATS 2.0 → Новый эксперимент**:

- **Запасных комплектов на дрона**: 0–64; комплект соответствует установленным
  батареям конкретного дрона. Для четырёх двухмодульных дронов два комплекта означают
  16 дополнительных физических модулей на общем складе.
- **Запасных модулей Крота**: 0–128, сверх установленных слотов.

Это начальный запас нового прогона. Масса и начальная энергия каждого модуля
учитываются; дополнительные батареи не появляются в текущей миссии при сохранении
конфигурации. Масса склада входит в массу базы уже до первого шага. Без явных флагов
сохраняется резерв загруженной конфигурации, явные флаги применяются после загрузки:

```bash
python -m ats --mode logistics --drone-spare-sets 2 --excavator-spare-batteries 4
python -m ats --headless --preset medium --mode logistics --steps 345600 --drone-spare-sets 2 --excavator-spare-batteries 4 --json reserves.json
python -m ats --configuration experiment.json --drone-spare-sets 3
```

## Контрольные прогоны

Один рельеф medium/seed42, четыре двухмодульных дрона, восемь контейнеров,
четыре порта снятых модулей, 20 м² панелей, лазер выключен. Меняются только запас
и число посадочных доков. Максимум четыре дня, все семь миссий завершились.
Критерий ложного простоя: два готовых свободных копателя с реальным доступным
рейсом одновременно ждут вне группового переноса, перестановки Крота и обслуживания.
Он измеряется без изменения зарядных запросов.

Во всех семи прогонах **ложный простой — 0 с**, ошибка массы 0 кг, максимальная
ошибка энергии 4,86e-6 Дж. Физические ID батарей сохранены. Ускорение с большим
числом запасных комплектов включает явно увеличенную стартовую энергию; это
не сравнение при одинаковом запасе энергии. Дополнительные батареи Крота при двух
комплектах дронов здесь не помогают: миссия заканчивается до его первой замены.

## Тесты

**168 тестов прошли за 142,25 с** на Linux / Python 3.12.14 / PySide6-Essentials 6.12.0.
[JUnit](ats2/spares-tests-312.xml). После дополнительной проверки сохранения роли
выделенного копателя также повторены все новые проверки и связанные сценарии.

Новые проверки покрывают запас, физические количества, массу базы на нулевом шаге,
начальную энергию, сохранение/загрузку JSON, CLI-переопределения, ограничения ввода,
параллельное копание при заряжающемся перевозчике, запрос зарядки по бюджету рейса,
полную зарядку перед подъёмом и запрет вылета с чужим грейфером. Пять основных
регрессионных тестов диспетчера отдельно запускались на прежнем коде: все падали.
